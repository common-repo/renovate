# renovate

Reusable common-repo template for self-hosted Renovate that bumps `.common-repo.yaml` upstream refs. Consumer contract: [README.md](README.md).

## Layout

- `.common-repo.yaml` — `self:` maintains this repo (common-repo/upstream plus its own payload); the outer pipeline exports `src/**` into consumer roots and marks the workflow as a template.
- `src/.github/workflows/renovate.yaml` — templated runner: write App token for the repo only, read-only token plus per-repo host rules for `RENOVATE_EXTRA_REPOSITORIES`, pinned common-repo CLI, Renovate action with the global config.
- `src/.github/renovate-global.json` — global config: common-repo regex managers, the `common-repo apply` post-upgrade rule, `allowedCommands`, and overridable defaults. Must not use a Renovate repo-config filename (`renovate.json`, `.github/renovate.json`, ...).
- `script/test` — template-var, config, extraction and consumer-fixture checks; `tests/` holds the extraction fixture and its matcher.
- Root `.github/`, `cog.toml`, `.pre-commit-config.yaml` — generated by the `self:` block; `.github/workflows/consumer-fixture.yaml` is hand-written.
- Keep agent indexes outside `src/`: every payload file is exported to consumers.

## Tools and validation

- Run `prek install` on new checkouts/worktrees; validate with `prek run --all-files`, `common-repo validate`, `common-repo apply --dry-run`, and `script/test`.
- `script/test` needs Python 3, `common-repo`, and `renovate-config-validator` (npm `renovate`); missing tools are skipped unless `REQUIRE_TOOLS=1`.
- Keep the source `template-vars` and the workflow's `__COMMON_REPO__` sentinels in sync (`script/test` checks), and the defaults identical in the `self:` and source blocks.
- Changing a matcher: update `tests/fixtures/` and the README syntax section in the same change.

## Maintaining this index

- Update the affected `AGENTS.md` files in the same change when paths, responsibilities, commands, dependencies, or conventions change.
- Keep indexes brief: record semantic entry points and non-obvious constraints; link to existing documentation instead of duplicating it.
- Add a directory index only when it provides useful navigation beyond its parent; omit generated, vendored, and fixture trees.
- Do not add `CLAUDE.md` files; Claude Code reads `AGENTS.md` natively, and a `CLAUDE.md` anywhere in the tree stops every `AGENTS.md` from loading.
